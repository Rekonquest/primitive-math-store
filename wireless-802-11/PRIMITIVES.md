# Wireless 802.11 — Primitive Reserve

> Cross-domain root atoms: **scan · hash · fold · project · scale · compare · combine · order**
> See `_taxonomy-root/ROOT_ATOMS.md` for the canonical definitions these specialize from.

This domain covers the standard-specific PHY and MAC-framing primitives that
show up in every 802.11 waveform but do **not** already live in
`signal-processing-rf/` or `information-theory-coding/`. The generic pieces
(FFT, matched filter, convolutional encoder/Viterbi decoder, OFDM subcarrier
map, CRC) are still sourced from those existing domains; this file only names
the pieces that were missing.

Implementation lives in `C:\Projects\Primitive math wifi\wifi-kit`. Reuse
from there rather than rewriting.

## Data Whitening

### scrambler (cross-domain alias: `pn-whiten`, `spread-lite`, `hash`)
**Domain:** Wireless 802.11
**Definition:** XOR the data stream with a length-127 pseudo-random sequence
generated by the polynomial `S(x) = x^7 + x^4 + 1`. Whitens the payload so
long runs of ones or zeros do not create narrowband spectral spikes or
starve the DC-null OFDM carrier. Self-inverse — descrambling is the same
operation with the same seed.
**Atom or composite:** Composite: `hash` (LFSR PN generator) + XOR.
**Cost model:** One shift-register update and one XOR per bit. Trivial.
**Real wall?** No — a *painted* wall on the DC-block problem. Scramble routes
around it; nothing information-theoretic is at stake.
**Cross-domain wiring:** Same shape as DSSS `spread`; same shape as a linear
`hash`.
**Notes:** Any nonzero 7-bit seed works; TX and RX must agree. See
`recover_seed_from_service_prefix` for the 802.11 SERVICE-based seed
exchange.

### recover-seed-from-service (cross-domain alias: `linear-solve`, `project^-1`)
**Domain:** Wireless 802.11
**Definition:** Given the first seven scrambled bits of the SERVICE field
(whose pre-scramble content is all zero), recover the transmit-side
scrambler seed by inverting the LFSR's autonomous state → output map.
**Atom or composite:** Composite: brute-force check of all 127 candidate
seeds; equivalent to a 7×7 GF(2) linear solve.
**Cost model:** 127 × 7 XORs. Negligible.
**Real wall?** No.
**Cross-domain wiring:** Same shape as spreading-code identification in DSSS
receivers, and as the linear-state-inference step in any autonomous LFSR
cryptanalysis.

## Bit Interleaving

### interleaver (cross-domain alias: `permutation`, `project`, `burst-diffusion`)
**Domain:** Wireless 802.11
**Definition:** Two-nested fixed permutation on the `N_CBPS`-bit block of
coded bits produced per OFDM symbol. Converts a subcarrier-localised burst
error into scattered single-bit errors that the convolutional decoder can
correct. Fully deterministic; the deinterleaver applies the inverse.
**Atom or composite:** Composite: two `project` steps.
**Cost model:** Precompute the permutation table once; then O(N_CBPS)
copies per OFDM symbol. Negligible.
**Real wall?** No.
**Cross-domain wiring:** Any code that assumes IID errors but faces bursty
channels wants a matching interleaver.
**Notes:** The formula `s = max(N_BPSC/2, 1)` generalises across BPSK,
QPSK, 16-QAM, 64-QAM — one implementation covers all four modulations.

## OFDM Pilot Management

### pilot_insert / pilot_extract (cross-domain alias: `beacon-inject`, `combine`, `scan`)
**Domain:** Wireless 802.11
**Definition:** Insert 4 known BPSK pilot symbols at FFT bins ±7, ±21 before
IFFT; extract them from the FFT bins after RX. Combined with the polarity
sequence `p_n`, they let the receiver track residual phase / channel-drift
across the frame.
**Atom or composite:** Atom (indexed stores/loads).
**Cost model:** 8 memory operations per OFDM symbol. Free.
**Real wall?** No.
**Cross-domain wiring:** Same shape as radar reference pulses and embedded
watermarks in graphics.

### pilot_polarity (cross-domain alias: `pn-polarity`, `sign-modulate`)
**Domain:** Wireless 802.11
**Definition:** The length-127 sign sequence `p_n ∈ {+1, −1}` generated by
the same `x^7 + x^4 + 1` LFSR as the scrambler but with the initial state
all-ones. Applied to the four pilot symbols on each OFDM symbol so pilots
carry `{+1, +1, +1, −1} · p_n`.
**Atom or composite:** Composite: `hash` (LFSR) + sign encoding.
**Cost model:** Precompute once (127 entries); O(1) lookup per symbol.
**Real wall?** No.
**Notes:** Without `p_n`, per-symbol pilot phases would appear identical
and residual CFO/SFO could not be distinguished from a static bias.

## Sampling-Frequency Offset

### sfo_estimate (cross-domain alias: `phase-slope`, `fold`)
**Domain:** Wireless 802.11
**Definition:** Estimate the fractional sampling-clock offset `ε` between TX
and RX from the *slope* of accumulated pilot-subcarrier phase across OFDM
symbols. Combines with per-symbol pilot phase tracking for the total
CFO+SFO story.
**Atom or composite:** Composite: `fold(sum)` of pilot phases + `project`
(least-squares).
**Cost model:** One least-squares fit over `4 · N_sym` samples per frame.
**Real wall?** No.
**Cross-domain wiring:** Any linear-drift estimator (GPS carrier phase,
crystal-oscillator regression, motor-encoder tick drift) is the same
primitive.

### common_phase_track (cross-domain alias: `pilot-derotate`, `combine`)
**Domain:** Wireless 802.11
**Definition:** For each DATA OFDM symbol, compute the mean phase of the
four residual pilot values (observed / expected), and de-rotate all 48 data
subcarriers by that phase. Cancels the per-symbol residual carrier phase
that survives LTF-based CFO correction. Essential for 64-QAM at long
frame lengths.
**Atom or composite:** Composite: `combine` (average of complex pilots) +
per-subcarrier `scale`.
**Cost model:** O(4 + 48) per OFDM symbol. Trivial.
**Real wall?** No — but the underlying phase-noise problem is real; without
tracking, long frames drift into constellation neighbours' basins.

## PLCP Header

### signal_field (cross-domain alias: `header-encode`, `header-decode`)
**Domain:** Wireless 802.11
**Definition:** The 24-bit SIGNAL header transmitted once per frame in a
BPSK-rate-1/2 OFDM symbol. Layout: 4-bit RATE + 1-bit reserved + 12-bit
LENGTH + 1-bit parity + 6-bit tail. Parity is even over bits 0–16; tail
forces the trellis back to state 0.
**Atom or composite:** Composite: bit-packing + XOR-fold parity.
**Cost model:** O(24) bit-level operations.
**Real wall?** No — a *painted* wall on receiver-side rate/length discovery.
Without SIGNAL, RX cannot know which MCS to use or how long the frame is.

### rate_table (cross-domain alias: `mcs-table`, `dispatch`)
**Domain:** Wireless 802.11
**Definition:** 802.11a Table 17-3: the eight rate points (6/9/12/18/24/36/
48/54 Mbps) and their associated modulation order, coding rate, N_BPSC,
N_CBPS, N_DBPS. A rate is the primary "policy dispatch" that turns SIGNAL
into concrete parameters for the rest of the receive chain.
**Atom or composite:** Data — but "dispatch on rate" is a first-class atom
in every 802.11 receiver.
**Real wall?** No.
**Notes:** The higher-throughput rates trade coding gain for spectral
efficiency; the Shannon capacity of the 20 MHz channel at a given SNR is
the real wall.

## Preamble (STF / LTF)

### stf (short training field) (cross-domain alias: `coarse-sync`, `preamble-lite`)
**Domain:** Wireless 802.11
**Definition:** 160-sample training sequence built from 12 specific ±(1+j)
values on every fourth subcarrier (Table 17-4), scaled by √(13/6). The
resulting time-domain sequence has period 16 samples, giving 10 identical
repetitions used for coarse timing + coarse CFO estimation via
autocorrelation.
**Atom or composite:** Composite: `combine` (sparse subcarrier fill) +
IFFT + periodic replication.
**Cost model:** One 64-point IFFT + 10 memcpys of 16 samples.
**Real wall?** No.

### ltf (long training field) (cross-domain alias: `fine-sync`, `channel-probe`)
**Domain:** Wireless 802.11
**Definition:** 160-sample sequence = 32-sample guard interval (GI2) + 2
back-to-back copies of a 64-sample OFDM symbol whose frequency-domain
content is ±1 on every used subcarrier (Table 17-5). Provides fine timing,
fine CFO (from the identical halves), and a per-subcarrier channel estimate.
**Atom or composite:** Composite: `combine` (dense subcarrier fill) + IFFT
+ CP + repetition.
**Cost model:** One 64-point IFFT + memcpys.
**Real wall?** No — but the channel-estimator's variance scales with 1/SNR,
so LTF quality bounds the receiver's noise floor.

### schmidl_cox_sync (cross-domain alias: `autocorrelate`, `normalised-corr`)
**Domain:** Wireless 802.11
**Definition:** Sync using STF's 16-sample period via double-window
autocorrelation (Schmidl-Cox-style) or using LTF via normalised
cross-correlation against a 128-sample double-LTF template. The
implementation in `wifi-kit::sync::frame_sync` uses normalised
cross-correlation with an earliest-peak-above-threshold rule for streaming.
**Atom or composite:** Composite: `project` + `scale` + `order`.
**Real wall?** No — but the sync-error probability at low SNR is the real
"can we even receive this" wall.

## Peak-to-Average Power Ratio Control

### papr_reduce (cross-domain alias: `clip`, `scale`, `tone-inject`)
**Domain:** Wireless 802.11
**Definition:** Reduce the peak-to-average power ratio of an OFDM
time-domain symbol before it hits a nonlinear power amplifier. Soft
clipping scales samples above a magnitude threshold down to it; tone
injection adds perturbations on unused subcarriers.
**Atom or composite:** Composite: `compare` (magnitude vs. threshold) +
`scale`.
**Cost model:** O(N) per OFDM symbol for clipping.
**Real wall?** Yes on the amplifier side — the PA has a real compression
point (P1dB) and running over it generates spectral regrowth that the
FCC/ETSI mask limits enforce.
**Cross-domain wiring:** Every OFDM/multicarrier system has this problem
(DVB-T, LTE, 5G). Loudness-limiting in audio is the same operation.

## MAC Framing

### mpdu_header (cross-domain alias: `framing`, `header-scan`)
**Domain:** Wireless 802.11
**Definition:** The 24-byte 802.11 MPDU header (3-address form): 2-byte
FrameControl (type, subtype, ToDS/FromDS bits, retry, etc.), 2-byte
Duration/ID, three 6-byte MAC addresses, 2-byte SequenceControl. Followed
by variable payload and a 4-byte FCS (CRC-32).
**Atom or composite:** Data layout + `scan` (byte-serial packing).
**Cost model:** Trivial (byte copies).
**Real wall?** No.
**Notes:** 3-address is the common case; 4-address (WDS) is a follow-up.
The FCS *algorithm* is the standard CRC-32/IEEE — the *value* is 802.11's
FCS.

### fcs (cross-domain alias: `crc32`, `checksum`)
**Domain:** Wireless 802.11
**Definition:** The 4-byte CRC-32 that terminates every MPDU. Polynomial
`0xEDB88320` reflected, init `0xFFFFFFFF`, final XOR `0xFFFFFFFF`.
**Atom or composite:** Composite: sourced from the general
`information-theory-coding::crc-checksum` primitive.
**Cost model:** ~4 ns per byte on a modern CPU (~1 cycle per bit at low
SIMD levels).

## Cross-Domain Summary

Every primitive in this file is a specialisation of a signal-processing or
information-theory primitive that already lives elsewhere in the store:

| 802.11 primitive | Nearest store atom(s) |
|---|---|
| `scrambler` | `signal-processing-rf::spread`, `cryptography::hash` |
| `interleaver` | `information-theory-coding::interleave`, `project` root atom |
| `pilot_insert`/`pilot_extract` | `combine`/`scan` root atoms |
| `pilot_polarity` | `cryptography::pn-sequence` |
| `sfo_estimate` | `signal-processing-rf::carrier-sync` + LS fit |
| `common_phase_track` | `signal-processing-rf::phase-track` |
| `signal_field` | `information-theory-coding::header-encode` |
| `stf`/`ltf` | `signal-processing-rf::preamble` |
| `schmidl_cox_sync` | `signal-processing-rf::frame-sync` |
| `papr_reduce` | `signal-processing-rf::quantize` + `scale` |
| `mpdu_header` | `networking::framing` |
| `fcs` | `information-theory-coding::crc-checksum` |

**The value add is the specialisation, not the invention.** These primitives
exist because 802.11 pins the tap positions, the subcarrier indices, the
polynomial, the FFT size, the header layout — and those pins turn generic
operations into codable, testable primitives that compose into a real
waveform.
